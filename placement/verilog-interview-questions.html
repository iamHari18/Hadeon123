Language basics

Q1What is the difference between wire and reg?Easy

A wire models a physical connection; it has no storage and must be driven continuously, by an assign statement or a module output. A reg is a variable that holds its value until the next procedural assignment; it is assigned inside always or initial blocks. A reg does not always become a flip-flop: a reg assigned in a combinational always @(*) block synthesises to plain logic. In SystemVerilog, logic replaces both for most uses.

Q2What are the four logic values in Verilog?Easy

0, 1, x (unknown, or a conflict between drivers) and z (high impedance, undriven). Simulation shows x for uninitialised regs and for contention; synthesis treats x as don't-care. A tri-state buffer is written as assign y = en ? a : 1'bz;.

Q3What is the difference between == and ===?Easy

== is logical equality: if either operand has an x or z bit, the result is x. === is case equality: it compares x and z literally and always returns 0 or 1. === is for testbenches (for example checking that an output is not x); it is not synthesisable.

// a = 4'b10x1
(a == 4'b10x1)   // x
(a === 4'b10x1)  // 1

Q4What is the difference between a task and a function?Easy

functiontask
Timing controls (#, @, wait)Not allowedAllowed
Return valueExactly oneNone; uses output arguments
Can callOther functionsFunctions and tasks
Typical useCombinational helper (parity, encoding)Testbench sequences (drive a bus transaction)

Both are synthesisable only when they contain no timing controls.

Q5What does a parameter do, and how is it different from localparam and `define?Medium

parameter is a module constant that can be overridden per instance, which makes modules reusable: fifo #(.DEPTH(16)) u_fifo (...). localparam is a constant that cannot be overridden from outside; use it for values derived from parameters. ` define `` is a global text macro processed before compilation; it applies to every file compiled after it, which causes clashes in large projects, so prefer parameters.

Procedural blocks and assignments

Q6What is the difference between blocking (=) and non-blocking (<=) assignments?Easy

A blocking assignment executes immediately; the next statement sees the new value. A non-blocking assignment evaluates its right-hand side immediately but updates the left-hand side at the end of the time step, after all other blocks have evaluated. Rule: use <= in clocked (sequential) blocks and = in combinational blocks.

Q7What hardware do these two blocks produce?Medium

// Block A
always @(posedge clk) begin
  b = a;
  c = b;
end

// Block B
always @(posedge clk) begin
  b <= a;
  c <= b;
end

Block A: c gets the new b, which is a, so synthesis produces a flip-flop for b and c both loaded from a (the second flip-flop is effectively a copy). Block B: c gets the old b, so you get a two-stage shift register a → b → c. This is the most common Verilog interview question; explain it with the evaluate-then-update rule.

Q8How do you swap two registers in Verilog without a temporary variable?Medium

With non-blocking assignments both right-hand sides are read before either left-hand side changes:

always @(posedge clk) begin
  a <= b;
  b <= a;
end

With blocking assignments this fails: a = b; b = a; leaves both equal to the old b.

Q9What is the difference between always @(*) and listing signals in the sensitivity list?Medium

always @(*) (or @*) automatically includes every signal read in the block. A hand-written list such as always @(a or b) that forgets sel causes simulation–synthesis mismatch: the simulator will not re-run the block when sel changes, but synthesis ignores sensitivity lists and builds the full logic. Use @(*), or always_comb in SystemVerilog, which also checks the block for latches.

Q10What is the difference between initial and always blocks?Easy

An initial block runs once at time 0; an always block repeats forever. initial is mainly for testbenches (stimulus, clock setup, $dumpfile). Most ASIC synthesis tools ignore initial; many FPGA tools use it to set register power-up values, but you should not depend on it in portable RTL — use a reset.

Combinational logic coding

Q11Why does this code infer a latch, and how do you fix it?Medium

always @(*) begin
  if (en)
    y = a;
end

When en is 0, y is not assigned, so the block must remember its old value: that is a latch. Fix it by assigning y in every path, either with an else or a default at the top:

always @(*) begin
  y = 1'b0;          // default
  if (en) y = a;
end

The same applies to case statements without a default and to blocks with several outputs where some branches skip an output.

Q12Write a 4:1 multiplexer in Verilog.Easy

module mux4 (
  input  wire [3:0] d,
  input  wire [1:0] sel,
  output reg        y
);
  always @(*) begin
    case (sel)
      2'd0: y = d[0];
      2'd1: y = d[1];
      2'd2: y = d[2];
      default: y = d[3];
    endcase
  end
endmodule

A one-line alternative: assign y = d[sel];.

Q13What is the difference between case, casex and casez?Medium

case compares bit by bit including x and z. casez treats z (and ?) in either the case expression or the items as don't-care. casex treats both x and z as don't-care. casex is dangerous: an x on the selector in simulation can match an item and hide a bug that real hardware would show. Use casez with ? for priority decoders, and avoid casex in RTL.

Q14What is the difference between if-else chains and case in synthesis?Medium

An if-else-if chain implies priority: the first true condition wins, so synthesis builds a chain of multiplexers with the first condition nearest the output. A case with mutually exclusive items implies a parallel multiplexer. Modern tools optimise both well when conditions are truly exclusive, but deep if-else chains on timing-critical paths can add levels of logic. SystemVerilog unique case and priority case state the intent explicitly.

Sequential logic coding

Q15Write a D flip-flop with asynchronous active-low reset.Easy

always @(posedge clk or negedge rst_n) begin
  if (!rst_n)
    q <= 1'b0;
  else
    q <= d;
end

For a synchronous reset, remove negedge rst_n from the sensitivity list; the reset is then only seen at a clock edge.

Q16Compare synchronous and asynchronous reset.Medium

Synchronous resetAsynchronous reset
ActsOnly on a clock edgeImmediately
Needs a running clockYesNo
TimingReset is part of the data pathReset removal must meet recovery/removal checks
Glitch sensitivityFiltered by the clockA glitch can reset flops
Common practiceFPGA designs often prefer itASICs often use it with a synchroniser

The usual safe scheme is asynchronous assertion, synchronous de-assertion: the reset takes effect at once, but is released through a two-flip-flop synchroniser so all flops leave reset on the same clock edge.

Q17Write a 4-bit up counter with enable and synchronous reset.Easy

module counter4 (
  input  wire       clk, rst, en,
  output reg  [3:0] count
);
  always @(posedge clk) begin
    if (rst)
      count <= 4'd0;
    else if (en)
      count <= count + 4'd1;
  end
endmodule

It wraps from 15 to 0 naturally because the result is truncated to 4 bits.

Q18Write a rising-edge detector for a signal that is already synchronous to clk.Medium

reg sig_d;
always @(posedge clk) sig_d <= sig;
assign rise = sig & ~sig_d;   // one-cycle pulse
assign fall = ~sig & sig_d;

If sig comes from another clock domain or a button, pass it through a two-flip-flop synchroniser first.

Q19Write a two-flip-flop synchroniser.Medium

(* ASYNC_REG = "TRUE" *) reg s1, s2;   // FPGA hint: keep together
always @(posedge clk_dst or negedge rst_n) begin
  if (!rst_n) {s2, s1} <= 2'b00;
  else        {s2, s1} <= {s1, async_in};
end
assign sync_out = s2;

Use only for single-bit signals; buses need a handshake or an async FIFO.

Q20Write a clock divider by 3 with 50 % duty cycle.Hard

An odd divider needs both edges. Count 0–2 on the rising edge, make a signal high for one and a half cycles by OR-ing a rising-edge and a falling-edge version:

reg [1:0] cnt;
reg       p, n;
always @(posedge clk or posedge rst)
  if (rst) cnt <= 0;
  else     cnt <= (cnt == 2) ? 0 : cnt + 1;

always @(posedge clk or posedge rst)
  if (rst) p <= 0; else p <= (cnt == 0);   // high one cycle in three

always @(negedge clk or posedge rst)
  if (rst) n <= 0; else n <= p;            // same, half a cycle later

assign clk_div3 = p | n;                   // 1.5 cycles high, 1.5 low

In real FPGA designs, use a PLL/MMCM or a clock enable rather than logic-generated clocks.

FSM coding

Q21Show the recommended coding style for an FSM.Medium

Two or three blocks: a sequential block for the state register, a combinational block for next state (and outputs).

localparam IDLE = 2'd0, RUN = 2'd1, DONE = 2'd2;
reg [1:0] state, next;

always @(posedge clk or negedge rst_n)
  if (!rst_n) state <= IDLE;
  else        state <= next;

always @(*) begin
  next = state;            // default: stay
  case (state)
    IDLE: if (start)  next = RUN;
    RUN:  if (finish) next = DONE;
    DONE:             next = IDLE;
    default:          next = IDLE;
  endcase
end

assign busy = (state == RUN);   // Moore output

The default assignment and default branch prevent latches and recover from illegal states.

Q22Code a Mealy detector for the sequence 101 with overlap.Hard

localparam S0 = 2'd0, S1 = 2'd1, S10 = 2'd2;
reg [1:0] st, nx;
reg       y;

always @(posedge clk or negedge rst_n)
  if (!rst_n) st <= S0; else st <= nx;

always @(*) begin
  nx = S0; y = 1'b0;
  case (st)
    S0:  nx = x ? S1 : S0;
    S1:  nx = x ? S1 : S10;
    S10: begin
           nx = x ? S1 : S0;
           y  = x;          // saw 1-0-1
         end
    default: nx = S0;
  endcase
end

On the final 1 the machine goes to S1, because that 1 can start the next match (overlap). For non-overlapping detection it would return to S0.

Testbenches and simulation

Q23Write a basic testbench with a clock and a reset.Easy

`timescale 1ns/1ps
module tb;
  reg clk = 0, rst = 1, en = 0;
  wire [3:0] count;

  counter4 dut (.clk(clk), .rst(rst), .en(en), .count(count));

  always #5 clk = ~clk;          // 100 MHz

  initial begin
    $dumpfile("tb.vcd"); $dumpvars(0, tb);
    #20 rst = 0;
    en = 1;
    #200;
    if (count !== 4'd4) $display("FAIL count=%0d", count);
    else                $display("PASS");
    $finish;
  end
endmodule

A testbench has no ports; it instantiates the design under test and drives its inputs.

Q24What does `timescale 1ns/1ps mean?Easy

The first value is the time unit: #5 means 5 ns. The second is the precision: delays are rounded to 1 ps. If files are compiled with different timescales, delays can silently mean different things, so set it consistently in every file.

Q25What is the difference between $display, $monitor, $strobe and $write?Medium

TaskWhen it prints
$displayImmediately, with newline
$writeImmediately, without newline
$strobeAt the end of the current time step, after non-blocking updates
$monitorWhenever any listed argument changes (only one active at a time)

$strobe is the one to use to see the values after <= assignments have settled in that step.

Q26What is a race condition in Verilog simulation?Medium

When two blocks read and write the same variable in the same time step using blocking assignments, the result depends on which block the simulator runs first, which the language does not define. Example: one always @(posedge clk) a = b; and another always @(posedge clk) b = a;. Using non-blocking assignments for all clocked logic removes these races, because all right-hand sides are read before any update.

Q27Why should testbench stimulus change on the opposite clock edge or after a small delay?Medium

If the testbench changes inputs at exactly the same simulation time as the active clock edge, whether the DUT sees the old or new value depends on event ordering. Driving inputs on the negedge, or with @(posedge clk) #1, or using non-blocking assignments in the testbench, makes the timing unambiguous and closer to real setup/hold behaviour.

Synthesis and gotchas

Q28Which Verilog constructs are not synthesisable?Easy

Delays (#10), initial blocks (on most ASIC flows), $display and other system tasks, === and !==, force/release, fork/join, loops whose bounds are not constant, file I/O and real-number arithmetic. Synthesis ignores delays rather than failing, which is a classic source of simulation–synthesis mismatch.

Q29What does a for loop synthesise to?Medium

A for loop with constant bounds is unrolled into parallel hardware; it does not execute over several clock cycles. This counts the ones in an 8-bit vector in a single cycle using a chain of adders:

always @(*) begin
  ones = 0;
  for (i = 0; i < 8; i = i + 1)
    ones = ones + d[i];
end

If you want an operation spread over cycles, write a counter and an FSM instead.

Q30What is the difference between a generate block and a for loop inside always?Medium

A generate loop (with a genvar) replicates module instances, continuous assignments or always blocks structurally, for example 8 instances of a full adder. A for loop inside an always block replicates statements within one block. Both are unrolled at elaboration; generate is the only way to create a variable number of instances.

Q31What causes simulation–synthesis mismatch? Give four causes.Hard

  1. Incomplete sensitivity lists (synthesis builds full logic, simulation does not re-evaluate).
  2. Delays in RTL, which synthesis ignores.
  3. casex/x handling: simulation x behaviour differs from real gates.
  4. Blocking assignments in sequential logic that create order-dependent behaviour.
  5. Relying on initial values that the target technology does not support.

Catch them with lint tools and gate-level simulation of the synthesised netlist.

Q32Why should you not generate clocks with logic or gate them with an AND gate in RTL?Hard

A clock made by combinational logic can glitch, and its delay is not balanced by the clock tree, so timing analysis treats it as a new, skewed clock domain. A glitch on an AND-gated clock can produce a runt pulse that clocks some flops and not others. For FPGAs, use clock enables (if (en) q <= d;) or dedicated clock buffers. For ASICs, use an integrated clock-gating cell (latch + AND) that only changes the enable while the clock is low.

How to prepare

Verilog interviews test whether you think in hardware. For every snippet, the expected answer is "this becomes these flip-flops and this logic", not a description of the code as a program.

  1. Master the blocking/non-blocking rule and be able to draw the hardware for any 3–4 line always block.
  2. Write these from memory, without a reference: D flip-flop (both resets), counter, shift register, mux, decoder, edge detector, synchroniser, FSM (Moore and Mealy), FIFO (synchronous), clock divider (even and odd).
  3. Simulate everything you write. Icarus Verilog + GTKWave is free and runs on any laptop. EDA Playground runs in a browser.
  4. Read a synthesis report once. Synthesise a small design (Yosys, Vivado or Quartus) and check the flip-flop and LUT count against what you expected.
  5. Learn a little SystemVerilog: logic, always_ff, always_comb, enum for states. Many companies now ask SV for verification roles.

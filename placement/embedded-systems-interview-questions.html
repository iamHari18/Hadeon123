Microcontrollers and architecture

Q1What is the difference between a microprocessor and a microcontroller?Easy

A microprocessor is a CPU on a chip; RAM, flash, timers and I/O are external chips (for example the processor in a laptop). A microcontroller puts the CPU, flash, RAM, timers, ADC, communication peripherals and GPIO on one chip, for a dedicated control task with low power and low cost (for example an STM32 or an ATmega328P). Microcontrollers usually run bare-metal code or a small RTOS; microprocessors usually run a full operating system with an MMU.

Q2Compare Harvard and von Neumann architectures.Easy

von NeumannHarvard
Memory busesOne shared bus for code and dataSeparate buses for code and data
Fetch and data accessCannot overlapCan happen in the same cycle
ExamplesClassic x86 model, MSP430AVR, PIC, DSPs

Most modern cores, including Cortex-M3/M4, use a modified Harvard design: separate instruction and data buses internally, but one unified address space so code can read constants from flash.

Q3Compare RISC and CISC.Easy

RISC uses a small set of simple, fixed-length instructions that mostly execute in one cycle, with a load–store design (only load and store touch memory) and many registers. This makes pipelining easy. CISC has many complex, variable-length instructions that can operate directly on memory, giving denser code but harder decoding. ARM and RISC-V are RISC; x86 is CISC externally but translates to RISC-like micro-operations internally.

Q4What happens between power-on and main() on a Cortex-M microcontroller?Medium

  1. The core reads the initial stack pointer from address 0x0000_0000 and the reset handler address from 0x0000_0004 (the vector table).
  2. The reset handler (startup code, usually assembly or C) runs.
  3. It copies initialised global variables (.data) from flash to RAM.
  4. It zeroes uninitialised globals (.bss).
  5. It configures the clock system (often in SystemInit), and in C++ calls global constructors.
  6. It calls main().

This is why a global int x = 5; uses both flash (the initial value) and RAM (the variable).

Q5What is a watchdog timer, and how should it be serviced?Medium

A watchdog is a hardware timer that resets the microcontroller if software does not "kick" (reload) it within a timeout. It recovers a system stuck in an infinite loop, a deadlock or a corrupted state. Kick it from one place in the main loop or a supervisor task, only after confirming that all critical tasks have reported progress. Kicking it from a timer interrupt is a common mistake: the interrupt keeps running even when the main code has hung, so the watchdog never fires.

C for embedded

Q6What does the volatile keyword do, and when must you use it?Easy

volatile tells the compiler that a variable can change outside the normal flow of the code, so every read and write must actually access memory and cannot be cached in a register or optimised away. Use it for:

  • Memory-mapped peripheral registers.
  • Global variables shared between an ISR and main code.
  • Variables shared between RTOS tasks (along with proper synchronisation).
volatile uint8_t flag = 0;
void UART_IRQHandler(void) { flag = 1; }
int main(void) {
    while (!flag) { }   /* without volatile this can become an infinite loop */
}

volatile does not make an operation atomic and does not replace a mutex or disabling interrupts.

Q7Can a variable be both const and volatile?Medium

Yes. const volatile means the program must not write to it, but its value can still change from outside, so every read must go to memory. Classic example: a read-only hardware status register.

#define STATUS (*(const volatile uint32_t *)0x40011000u)

Q8Write macros to set, clear, toggle and test bit n of a register.Easy

#define SET_BIT(r, n)    ((r) |=  (1u << (n)))
#define CLEAR_BIT(r, n)  ((r) &= ~(1u << (n)))
#define TOGGLE_BIT(r, n) ((r) ^=  (1u << (n)))
#define TEST_BIT(r, n)   (((r) >> (n)) & 1u)

Use 1u (unsigned) so that shifting into bit 31 is well-defined; 1 << 31 on a 32-bit int is undefined behaviour.

Q9How do you check if a number is a power of two, and count the set bits?Medium

int is_pow2(uint32_t x) { return x && !(x & (x - 1)); }

int popcount(uint32_t x) {
    int c = 0;
    while (x) { x &= x - 1; c++; }   /* clears the lowest set bit each pass */
    return c;
}

x & (x − 1) clears the lowest set bit; a power of two has only one set bit, so the result is 0. The loop runs once per set bit (Kernighan's method).

Q11How do you access a memory-mapped register at a fixed address?Medium

Cast the address to a pointer to a volatile type and dereference it:

#define GPIOA_ODR (*(volatile uint32_t *)0x40020014u)
GPIOA_ODR |= (1u << 5);     /* drive PA5 high */

Vendor headers do the same with structs: GPIOA->ODR |= (1u << 5);, where GPIOA is a pointer to a struct whose members are laid out at the register offsets.

Q12What is endianness, and how can you detect it in C?Medium

Endianness is the byte order of multi-byte values in memory. Little-endian stores the least significant byte at the lowest address (ARM Cortex-M default, x86); big-endian stores the most significant byte first (network byte order).

uint32_t x = 1;
int little = (*(uint8_t *)&x == 1);

It matters when sending binary data over a bus or network, or reading a sensor that sends MSB first.

Q13What is structure padding, and how do you avoid surprises?Medium

Compilers insert padding so each member sits at an address that is a multiple of its alignment. struct { uint8_t a; uint32_t b; uint8_t c; } is typically 12 bytes, not 6. Reordering members from largest to smallest (b, a, c) shrinks it to 8. __attribute__((packed)) removes padding but can cause slow or faulting unaligned access on some cores. Never send a struct over a link with memcpy and assume the other side has the same layout; serialise field by field.

Q14What is the difference between static global, static local and extern?Medium

  • static local variable: keeps its value between function calls; stored in .data/.bss, not on the stack.
  • static global variable or function: visible only inside its source file (internal linkage), which avoids name clashes.
  • extern: declares a variable defined in another file; it does not allocate storage.

Q15Why is dynamic memory allocation (malloc) avoided in many embedded systems?Hard

Heap allocation has non-deterministic timing, can fail at run time, and causes fragmentation: after many allocations and frees of different sizes, there may be enough total free memory but no single block big enough. On a device that must run for years without a reboot, this is a slow-moving crash. Safety standards such as MISRA C restrict it. Alternatives: static allocation, fixed-size memory pools (block allocators), and allocating everything once at start-up.

Interrupts

Q16What happens when an interrupt occurs on a Cortex-M?Easy

  1. The current instruction completes (or is abandoned and restarted, for some multi-cycle instructions).
  2. The hardware pushes R0–R3, R12, LR, PC and xPSR onto the stack automatically.
  3. The ISR address is fetched from the vector table and the core runs it.
  4. On return, the saved registers are restored and the interrupted code continues.

Because the hardware stacking follows the C calling convention, Cortex-M ISRs can be plain C functions.

Q17What are good practices for writing an ISR?Easy

  • Keep it short: clear the flag, move data to a buffer, set a flag, return.
  • No blocking calls, no printf, no long loops, no malloc.
  • Mark shared variables volatile and protect multi-byte shared data.
  • Clear the interrupt source flag, or the ISR re-enters immediately.
  • Defer heavy work to the main loop or an RTOS task.

Q18What is interrupt latency, and what affects it?Medium

Latency is the time from the interrupt request to the first instruction of the ISR. It depends on the core's fixed entry cost (12 cycles on Cortex-M3/M4 with zero-wait-state memory), on the instruction being executed, on higher-priority ISRs that are running, on sections of code that disable interrupts, and on flash wait states. Long critical sections are usually the biggest contributor in real firmware.

Q19What is a nested vectored interrupt controller (NVIC)?Medium

The NVIC is the Cortex-M interrupt controller. "Vectored": each interrupt has its own entry in a table of handler addresses, so no software polling is needed to find the source. "Nested": a higher-priority interrupt can pre-empt a lower-priority ISR. It also supports tail-chaining (moving straight to the next pending ISR without unstacking and restacking) and late arrival optimisation, both of which cut latency.

Q20How do you safely read a 32-bit counter updated in an ISR on an 8-bit microcontroller?Hard

An 8-bit CPU reads the 4 bytes in separate instructions. If the ISR updates the counter between them, you get a torn value (some old bytes, some new). Options:

uint32_t read_ticks(void) {
    uint32_t t;
    cli();            /* disable interrupts */
    t = ticks;
    sei();            /* re-enable (better: restore the previous state) */
    return t;
}

Or read twice until two consecutive reads match. On a 32-bit core, an aligned 32-bit read is atomic, but read-modify-write (ticks++ in both contexts) is still not.

Q22Explain a UART frame. What does 9600 8N1 mean?Easy

Idle line is high. A frame is: 1 start bit (low), 5–9 data bits (LSB first), an optional parity bit, then 1 or 2 stop bits (high). 9600 8N1 means 9600 baud, 8 data bits, no parity, 1 stop bit: 10 bits per byte, so the maximum throughput is 960 bytes/s. Both ends must agree on the baud rate within about ±2–3 %, because the receiver samples each bit relative to the start-bit edge.

Q23Why does I2C need pull-up resistors, and how do you choose their value?Medium

I2C devices only pull the lines low (open-drain); a resistor pulls the line high when no one is driving. This allows wired-AND behaviour, which enables multi-master arbitration and clock stretching. The value is a trade-off: too large and the bus capacitance makes rise time too slow; too small and devices cannot sink the current (3 mA limit in standard and fast mode).

Rmax ≈ tr / (0.8473 · Cbus), Rmin = (VDD − 0.4 V) / 3 mA

At 400 kHz (tr = 300 ns) with 100 pF, Rmax ≈ 3.5 kΩ; at 3.3 V, Rmin ≈ 970 Ω. 2.2 kΩ is a common choice.

Q24Describe an I2C transaction.Medium

  1. START: SDA goes low while SCL is high.
  2. Master sends the 7-bit address plus R/W bit; the addressed slave pulls SDA low on the 9th clock (ACK).
  3. Data bytes follow, 8 bits each, MSB first, each followed by an ACK (or NACK from the master to end a read).
  4. STOP: SDA goes high while SCL is high. A repeated START lets the master change direction without releasing the bus, for example "write register address, then read data".

SDA may only change while SCL is low, except for START and STOP.

Master and slave must use the same mode. Mode 0 and mode 3 are the most common. Getting this wrong typically shows as data shifted by one bit.

Q26What is CAN, and why is it used in vehicles?Medium

Controller Area Network is a two-wire differential, multi-master bus (CAN_H, CAN_L) with 120 Ω terminations at each end. Messages carry an identifier instead of a destination address; bitwise arbitration on the identifier means the lowest ID (highest priority) wins without corrupting the frame. It has CRC, ACK, error counters and automatic fault confinement, which makes it robust in electrically noisy cars. Classic CAN runs up to 1 Mbit/s; CAN FD allows larger payloads and faster data phases.

RTOS basics

Q27What is an RTOS, and when do you need one?Easy

A real-time operating system schedules tasks so that deadlines are met predictably. "Real-time" means deterministic, not necessarily fast. You need one when the firmware has several independent activities with different timing needs (for example a control loop every 1 ms, a communication stack, a user interface) that are hard to manage in a single super-loop. FreeRTOS, Zephyr and ThreadX are common.

Q28Compare a mutex and a semaphore.Medium

MutexBinary semaphoreCounting semaphore
PurposeMutual exclusion over a shared resourceSignalling an eventCounting available resources
OwnershipOnly the task that took it can give itNo ownerNo owner
Priority inheritanceUsually yesNoNo

Use a mutex to protect a shared peripheral; use a semaphore for an ISR to wake a task.

Q29What is priority inversion and how is it solved?Hard

A low-priority task L holds a mutex. A high-priority task H blocks waiting for it. A medium-priority task M, which does not need the mutex, pre-empts L and runs for a long time, so H is effectively blocked by M. This caused resets on the Mars Pathfinder lander in 1997. Solutions: priority inheritance (L temporarily runs at H's priority while holding the mutex), priority ceiling (the mutex raises its holder to a preset maximum priority), or redesigning to avoid sharing.

Q30What is a deadlock, and what are the four conditions for it?Medium

A deadlock is when two or more tasks wait for each other forever. All four Coffman conditions must hold: mutual exclusion, hold and wait, no pre-emption of resources, and circular wait. The simplest prevention in firmware is to always acquire multiple locks in the same global order, which removes circular wait. Using timeouts on lock calls also lets the system detect and recover.

Q33How do you detect a stack overflow on a microcontroller?Medium

  • Stack painting: fill the stack with a known pattern (0xDEADBEEF) at start-up and check later how much has been overwritten (the high-water mark).
  • MPU guard region: set a no-access region below the stack so an overflow causes a fault instead of silent corruption.
  • RTOS checks: FreeRTOS can check a canary at each context switch.
  • Static analysis: GCC's -fstack-usage reports per-function stack use for worst-case estimates.

Symptoms of undetected overflow are random variable corruption and hard faults that move around when unrelated code changes.

Peripherals and I/O

Q34What is PWM, and how is duty cycle used?Easy

Pulse-width modulation switches a pin between high and low at a fixed frequency; the duty cycle is the fraction of each period that it is high. The average voltage is duty × Vhigh, so 25 % on a 3.3 V pin averages 0.825 V. PWM drives LED brightness, DC motor speed, servos (1–2 ms pulse every 20 ms) and, with an RC filter, a crude DAC. In a timer, frequency = timer clock / ((prescaler + 1)(ARR + 1)) and duty = CCR / (ARR + 1).

Q35What is ADC resolution, and what is the LSB size of a 12-bit ADC at 3.3 V?Easy

Resolution is the number of output codes: an n-bit ADC has 2n levels. The LSB (step size) is Vref/2n: 3.3 V / 4096 ≈ 0.806 mV. Ideal quantisation SNR is 6.02n + 1.76 dB, about 74 dB for 12 bits. Real ADCs are specified by ENOB (effective number of bits), which accounts for noise and distortion and is always lower.

Q36Why do you need to debounce a push button, and how?Medium

A mechanical contact bounces for roughly 1–20 ms when pressed or released, producing many transitions that firmware reads as multiple presses. Hardware fix: an RC filter followed by a Schmitt-trigger input. Software fix: sample the pin periodically (for example every 5 ms) and accept a new state only after it has been stable for several samples, or ignore further edges for a set time after the first edge. Avoid long delay() calls inside an interrupt to debounce.

Q37What is DMA and why is it useful?Medium

Direct memory access lets a peripheral move data to or from memory without the CPU copying each byte. The CPU sets source, destination, length and trigger, then continues; the DMA raises an interrupt when done (or half done, for double buffering). It is used for ADC sampling, UART/SPI streams, audio and display updates. It reduces CPU load and power and makes data timing more regular. Watch for cache coherency on cores with a data cache, and do not touch a buffer while DMA is writing it.

Q38What are pull-up and pull-down resistors, and what is an open-drain output?Medium

A pull-up (or pull-down) resistor gives an input a defined level when nothing is driving it, so it does not float and pick up noise. An open-drain (open-collector) output can only pull low; the high level comes from a pull-up. This allows several outputs to share a line (wired-AND), level shifting to a different voltage, and is required by I2C. A push-pull output actively drives both high and low and is faster, but two push-pull outputs fighting each other can be damaged.

How to prepare

Embedded interviews have three parts: C questions (often written on paper), hardware/protocol questions, and "tell me about your project". The third decides most offers, so build at least one project you can explain down to the register level.

  1. C first. Practise bit manipulation, pointers, volatile, const, structs, unions and storage classes until you can answer without hesitating. Write small programs and inspect the output.
  2. Read one datasheet chapter properly — the GPIO, timer and UART chapters of the microcontroller you use. Interviewers ask "which registers did you configure?".
  3. Bring up a protocol without a library once: bit-bang UART or SPI on GPIO, or write a register-level I2C driver. Look at it on a logic analyser (cheap 8-channel analysers work with PulseView).
  4. Learn one RTOS lightly. Create two FreeRTOS tasks, a queue and a mutex. Know why each exists.
  5. Know your project's numbers: clock speed, sample rate, baud rate, power draw, flash/RAM usage, and why you chose them.

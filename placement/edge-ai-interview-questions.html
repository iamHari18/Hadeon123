Edge AI fundamentals

Q1What is edge AI, and why run inference on the device instead of the cloud?Easy

Edge AI means running a trained machine-learning model on the device that collects the data (a sensor node, phone, camera or microcontroller) rather than sending raw data to a server. Reasons:

  • Latency: no network round trip; a decision in milliseconds.
  • Privacy: raw audio or images never leave the device.
  • Bandwidth and cost: send only results ("door opened"), not continuous streams.
  • Availability: works without connectivity.
  • Energy: radio transmission often costs more energy than local computation.

Training usually still happens in the cloud or on a workstation; the edge device runs inference only.

Q2What is TinyML?Easy

TinyML is machine learning on microcontroller-class hardware: roughly tens to hundreds of kilobytes of RAM, up to a few megabytes of flash, clock speeds in the tens to hundreds of MHz, and power budgets in the milliwatt range or below. Typical tasks are keyword spotting ("Hey device"), anomaly detection on vibration data, gesture recognition from an accelerometer, and person detection on low-resolution images.

Q3What is the difference between training and inference?Easy

Training adjusts the model's weights using labelled data, forward and backward passes, and gradient descent; it needs high precision (usually FP32 or mixed precision) and lots of memory for activations and gradients. Inference only runs the forward pass with fixed weights to produce a prediction. Edge hardware is designed for inference: it can use low precision and has no need to store gradients.

Quantization

Q5What is quantization?Easy

Quantization stores weights and activations with fewer bits than 32-bit floating point, most often 8-bit integers. Benefits: 4× smaller model, integer arithmetic that is faster and far more energy-efficient on MCUs and NPUs, and less memory bandwidth. Cost: small rounding error that can reduce accuracy, usually by less than 1–2 percentage points for well-behaved models with 8-bit quantization.

Q6Explain affine (asymmetric) quantization with scale and zero point.Medium

A real value r is mapped to an integer q using a scale S and zero point Z:

r = S · (q − Z)
q = round(r / S) + Z, clamped to [qmin, qmax]

For int8, q ranges −128 to 127. If a tensor's range is [rmin, rmax], then S = (rmax − rmin) / 255 and Z is chosen so that r = 0 maps exactly to an integer. Example: range [−1.0, 3.0] → S = 4/255 ≈ 0.0157, Z = −128 + round(1.0/S) = −64. Exact zero matters because padding and ReLU outputs produce many zeros.

Q7What is the difference between symmetric and asymmetric quantization?Medium

Symmetric: Z = 0 and the range is ±max|r|, so S = max|r| / 127. Multiplication is simpler (no zero-point cross terms), which is why weights are usually quantized symmetrically. Asymmetric: Z ≠ 0, which uses the full integer range for skewed data such as ReLU activations (all non-negative). Common practice (for example TensorFlow Lite int8): symmetric per-channel weights, asymmetric per-tensor activations.

Q8What is per-tensor versus per-channel quantization?Medium

Per-tensor uses one scale for the whole weight tensor. Per-channel uses a separate scale for each output channel of a convolution. Channels can have very different weight ranges, and one large channel would otherwise force a coarse scale on all the others. Per-channel quantization of weights noticeably improves accuracy for depthwise convolutions in particular, at negligible cost.

Q10How is an int8 convolution actually computed without floating point?Hard

Each output is Σ (qw − Zw)(qx − Zx), accumulated in int32 to avoid overflow. The bias is pre-quantized to int32 with scale Sw·Sx. The int32 result must be rescaled to the output's int8 scale by the factor M = SwSx/Sy. Since M is a real number less than 1, it is stored as a fixed-point multiplier M0 (a 32-bit integer) and a right shift n, so M ≈ M0 · 2−n. After rescaling, add the output zero point Zy and clamp (which also implements ReLU or ReLU6 for free). Everything runs in integer arithmetic.

Pruning, distillation and model design

Q11What is pruning?Easy

Pruning removes weights or structures that contribute little to the output, typically those with the smallest magnitude, then fine-tunes the network to recover accuracy. Unstructured pruning zeroes individual weights; it reaches high sparsity but needs sparse-matrix support to actually run faster. Structured pruning removes whole channels, filters or layers; the result is a smaller dense network that speeds up on any hardware.

Q12Why doesn't 80 % unstructured sparsity give a 5× speed-up on a microcontroller?Medium

The zeros are scattered, so a dense kernel still multiplies them. Sparse formats (such as compressed sparse row) add index storage and irregular memory access that a simple MCU pipeline handles poorly. The model may compress well on disk, but runtime and RAM barely change unless the kernel library and hardware support sparsity. For MCU deployment, structured pruning or a smaller architecture usually gives a real speed-up.

Q13What is knowledge distillation?Easy

A small "student" network is trained to match the output probability distribution (soft labels) of a large, accurate "teacher" network, often in addition to the true labels. Soft labels carry information about which classes are similar, so the student learns more than it would from hard labels alone. It is used to get a model small enough for edge deployment with less accuracy loss.

Q14Why are depthwise separable convolutions used in edge models?Medium

A standard K × K convolution from Cin to Cout channels costs K2·Cin·Cout MACs per output pixel. A depthwise separable convolution splits it into a K × K depthwise convolution (one filter per input channel, K2·Cin) and a 1 × 1 pointwise convolution (Cin·Cout). The ratio is

1/Cout + 1/K2

For K = 3 and Cout = 64, that is about 0.13, roughly 8× fewer operations. MobileNet and many TinyML vision models are built on this.

Q15How do you count MACs and parameters for a convolution layer?Medium

For a convolution with K × K kernel, Cin input channels, Cout output channels, output size Hout × Wout:

Parameters = K2 · Cin · Cout (+ Cout biases)
MACs = K2 · Cin · Cout · Hout · Wout

Example: 3 × 3, 16 → 32 channels, 48 × 48 output: 4,608 weights (+32 biases) and about 10.6 million MACs. A fully connected layer with N inputs and M outputs has N·M weights and N·M MACs.

Hardware for edge inference

Q16What is an NPU, and how is it different from a CPU or GPU?Easy

A neural processing unit is a hardware block specialised for the operations in neural networks: large arrays of low-precision multiply-accumulate units, on-chip buffers to reuse weights and activations, and DMA to stream tensors. A CPU is general-purpose and sequential; a GPU has many general-purpose parallel cores and high power; an NPU trades flexibility for much higher operations per watt on supported layers. Unsupported operators fall back to the CPU, which can dominate run time.

Q18What does TOPS mean, and why is it a misleading benchmark?Medium

TOPS is tera (1012) operations per second, usually counting one MAC as 2 operations and quoted at peak utilisation and the lowest precision supported (often int8 or int4). Real workloads rarely reach peak: utilisation depends on layer shapes, memory bandwidth, and whether every operator runs on the accelerator. Compare devices with actual latency and energy per inference on your model, or on a standard benchmark such as MLPerf Tiny.

Q19Why is memory access often more expensive than computation in inference?Hard

Moving data costs energy proportional to distance. Reading from off-chip DRAM costs on the order of a hundred times more energy than an 8-bit MAC, and even on-chip SRAM reads cost more than the arithmetic. Accelerators therefore focus on data reuse: keeping weights stationary in local registers (weight-stationary dataflow), reusing input activations across output channels, and tiling layers to fit on-chip buffers. A layer with few MACs per byte moved (low arithmetic intensity), such as a depthwise convolution or a fully connected layer at batch size 1, is memory-bound rather than compute-bound.

Deployment and tools

Q20What is the typical workflow to deploy a model on a microcontroller?Easy

  1. Collect and label data from the real sensor.
  2. Train a small model (TensorFlow/Keras or PyTorch).
  3. Convert and quantize it (for example TensorFlow Lite with int8 PTQ, or export to ONNX).
  4. Generate a C array of the model or compile it with a vendor tool.
  5. Link it with an inference runtime (TensorFlow Lite for Microcontrollers, CMSIS-NN kernels, or a vendor runtime).
  6. Measure latency, RAM, flash and accuracy on the device, and iterate.

Q21What is TensorFlow Lite for Microcontrollers, and what is the tensor arena?Medium

TFLite Micro is an interpreter that runs .tflite models on bare-metal MCUs with no operating system, no dynamic memory allocation and no standard library dependencies. The tensor arena is a single static byte array that the application provides; the runtime plans all intermediate tensors inside it, reusing memory for tensors whose lifetimes do not overlap. You size it by trial: start large, check the reported usage, and trim. Only the operators the model uses need to be registered, which keeps flash small.

Q22How do you choose between accuracy, latency and power for an edge model?Medium

Fix the hard constraints first: the latency deadline (for example 100 ms per keyword window), the RAM and flash budget, and the energy per inference allowed by the battery life target. Then choose the most accurate model that meets them. Levers, roughly in order of impact: input size (image resolution, audio window length, sample rate), model width and depth, quantization precision, operator choice (use what the accelerator supports), and inference rate (run the model only when a cheap trigger such as a motion or sound-level threshold fires).

Q23How do you estimate battery life for an always-on edge AI sensor?Medium

Average current = (Iactive · tactive + Isleep · tsleep) / period. Example: inference takes 20 ms at 10 mA once per second, and sleep is 5 µA:

Iavg = (10 mA × 0.02 s + 0.005 mA × 0.98 s) / 1 s ≈ 0.205 mA

A 1000 mAh battery then lasts about 1000 / 0.205 ≈ 4,880 hours, roughly 6.7 months, before accounting for the sensor, radio, regulator losses and self-discharge. Duty-cycling, not raw speed, usually decides battery life.

Q24What is a cascade (wake-up) architecture in edge AI?Hard

A tiny, very low-power first stage runs continuously and only wakes a larger, more accurate model when it detects something of interest. Example: a 20 kB keyword-spotting model on a low-power core triggers a larger speech model on the main processor; or a motion detector triggers a person-detection CNN. The average power is dominated by the first stage, while accuracy is set by the second. The design question is the first stage's false-negative rate, because anything it misses is never seen by the second stage.

Q25How do you check that a quantized model behaves the same on device as in Python?Medium

Run the same test inputs through the quantized model in the Python interpreter (for example the TFLite interpreter on a PC) and on the device, and compare the int8 outputs. They should match exactly or within one or two LSBs if both use the same kernels. Then compare quantized and float accuracy on the full test set. Common causes of mismatch: different input preprocessing (scaling, mean subtraction, channel order) on the device, wrong input quantization parameters, and an operator falling back to a reference kernel with different rounding.

How to prepare

Edge AI roles sit between machine learning and embedded systems, and interviews test both. Most candidates know one side; knowing both is what gets you shortlisted.

  1. Get the embedded basics solid first (C, memory map, interrupts, DMA). Read the embedded systems questions.
  2. Learn quantization arithmetic by hand. Quantize a small vector with a scale and zero point on paper, then dequantize it and compute the error.
  3. Deploy one model end to end on a real board: an accelerometer gesture classifier or a keyword spotter. Record flash, RAM, latency and accuracy before and after int8 quantization. This becomes your interview project.
  4. Count MACs and parameters for a small CNN, layer by layer. Interviewers like this question because it shows whether you understand where cost comes from.
  5. Read one hardware paper or datasheet for an NPU and note its dataflow, supported operators and precision.
